# 크리스마스 빌리지: 1~25일 작업 계획

작성·최종 정리: **2026-11-05 (한국 시각)**

사용자가 확정한 두 표와 이미지 파일명을 다른 컴퓨터와 새 대화에서 이어서 구현하기 위해 기록한다. **전체 목표는 1~25일이며 현재 구현 완료는 1일·2일·12일뿐이다.** 아래 표의 상태 열과 실제 구현 기록을 구분해 읽는다. 오늘은 작업을 마무리하며 이 문서와 인수인계만 갱신했고, 새로운 날짜를 추가하지 않았다.

## 구현 방향

- `assets/images/advent/Viliage_Day0.png`를 기본 배경으로 사용한다.
- 날짜를 개봉하면 해당 날짜의 이미지 레이어를 위에 얹는다. 이미 개봉한 날짜의 변화는 누적해서 유지한다.
- `assets/images/advent/Viliage_Day25.png`는 완성 장면 참고용이다. 완성 이미지 전체로 화면을 교체하는 방식으로 만들지 않는다.
- 숫자는 아래 표의 위치에 배치한다. 숫자와 배지는 작고 반투명하게 유지해 배경을 가리지 않으며, 표시 크기와 터치 영역은 구분한다.
- 사용자가 마음에 들어 한 선물 제목·문구 팝업, 재열람, 개봉 기록 저장·복원을 유지한다.
- 전체 장면의 코드 이름은 `Village` / `village`로 통일한다. 빵집은 마을 안의 한 건물이다. 기존 가챠 기능과 티켓 기록을 보존한다.

## 이미지 파일명과 제작 기준

- 저장 폴더는 모두 `assets/images/advent/`다. 아래 표에는 폴더를 제외한 파일명만 적었다. 대소문자·공백·숫자 자릿수까지 표대로 저장한다.
- **한 날짜에 여러 투명 PNG를 연결하고, 그 날짜를 한 번 누르면 모두 함께 나타나게 한다.** 날짜마다 누르는 위치와 개봉 기록은 하나이며, 같은 날짜에 속한 모든 레이어가 같은 `dayId`와 `afterOpening` 조건을 사용한다. 파일별로 따로 누르는 방식이 아니다.
- 서로 다른 위치나 역할의 변화는 아래 표처럼 파일을 나눈다. 예를 들어 4일은 `Day04_PostOffice_Window.png`(불이 켜진 창문과 그 안의 편지·소포)와 `Day04_Mailbox_Letters.png`(우체통에 추가되는 편지)를 따로 저장하고 한 번에 표시한다.
- 같은 장면의 한 묶음은 함께 그린다. 예를 들어 보호자·아이 한 쌍, 세 가족, 선물을 든 주민과 손에 들린 상자는 해당 파일 하나에 포함한다. 각 파일명은 그 파일에 들어갈 대상이나 효과를 뜻한다.
- 1일은 현재 연결된 `Day1_Bakery Show Window.png`를 그대로 사용한다. 그 외 날짜는 `Day04_PostOffice_Window.png`처럼 `Day두자리날짜_대상.png`로 이름을 정한다. 현재 2일·12일 파일도 준비돼 연결됐으며, 미구현 날짜의 파일명은 제작 기준이다. 표에 이름이 있다는 것만으로 파일이 존재하거나 코드에 연결됐다는 뜻은 아니다. 이전에 제안한 `Village_Overlay_DayNN.png`라는 날짜당 한 장 방식은 이 목록으로 대체한다.
- 새 PNG의 전체 캔버스는 기본 배경과 같은 **1051 × 1496**으로 맞춘다. 배경 위에서 해당 물체가 있어야 할 위치에 그대로 그린 뒤, 나머지는 투명하게 두고 전체 캔버스로 내보낸다. 투명 여백을 자동으로 자르거나 그림만 따로 확대하지 않는다.
- **해당 파일에 지정된 새 변화만** 담는다. 이전 날짜의 변화와 마을 전체 배경을 함께 굽지 않는다. 같은 날짜의 다른 파일 내용을 중복해서 그리지 않는다. 각 날짜의 레이어가 쌓여 최종 장면을 완성한다.
- 기본 배경은 기존 이름인 `Viliage_Day0.png`를 유지한다. 기존 `Viliage_Day25.png`는 참고용 완성 이미지다. 25일에 실제로 얹을 파일은 `Day25_Tree_Star.png`, `Day25_Tree_Full_Glow.png`, `Day25_Santa_Sleigh.png` 세 개다. 썰매 파일에는 산타와 루돌프를 함께 넣는다.
- 트리 표에 적힌 파일은 날짜별 표에서 참조하는 동일 파일이다. 별도의 중복 파일을 제작하지 않는다. 24일 트리 표에는 트리 조명 파일만 표시하지만, 날짜별 표의 주민·건물 장식 파일도 24일에 함께 나타난다.

4일의 연결 예시(설명용이며 이번 요청에서 코드를 수정하지 않음):

```text
4일 숫자 한 번 클릭
  → 4일 개봉 기록 저장
  → Day04_PostOffice_Window.png 표시
  → Day04_Mailbox_Letters.png 표시
  → 4일 선물 문구 팝업 표시
```

숫자·클릭 영역·개봉 기록·선물 문구는 날짜당 하나이며, 이미지 레이어만 여러 개다. 이미지 앞뒤 순서는 구현 시 `zIndex`로 조정하고 파일명 순서에 의존하지 않는다.

## 기록 시점의 실제 구현 상태

- 2026-11-05 후속 반영: 현재 코드는 기본 마을 배경과 **1일 쇼윈도·2일 다락집 창문·12일 걷는 연인**을 연결했다. 나머지 날짜는 아직 계획이다. Day02와 Day12는 원본 배치대로 겹치며, 날짜 잠금·선물 팝업·누적 저장·복원을 지원한다.
- 사용자 선택에 따라 `Day02_Attic_Window.png` 전체를 2일에 표시하는 것으로 확정했다. 창문·실내 트리·양말·가랜드를 함께 표시하며, 원본을 분리하거나 수정하지 않는다. 날짜별 표에도 이 결정을 반영했고 11일의 대체 변화는 추후 결정한다.
- `lib/advent/village_config.dart`: `villageDays`, `villageLayers`, `villageHotspots`, 이미지 위치와 전환 설정.
- `lib/widgets/village_scene.dart`: `VillageScene`, 레이어 표시·전환, 숫자와 터치 영역.
- `lib/providers/advent_provider.dart`: 날짜 판정과 개봉 기록 저장·복원.
- `lib/pages/calendar_page.dart`: 장면 배치, 날짜 클릭 처리, 선물 팝업.
- 숫자 크기는 18, 배지는 34 × 32, 배지 배경 불투명도는 0.55로 줄인 상태다. 터치 영역은 별도로 유지한다.
- 기준 PNG는 1051 × 1496이다. 코드의 도화지는 가로 600, 세로 `600 * 1496 / 1051`로 원본 비율을 따른다.
- Day1 PNG는 전체 크기가 같아도 내부 쇼윈도 위치·크기가 달라 레이어 좌표를 보정했다. 이후 이미지도 파일 크기가 같다는 이유만으로 배치가 일치한다고 가정하지 않는다.
- 개봉 기록은 연도별 SharedPreferences에 저장한다. Git으로 코드를 옮겨도 다른 컴퓨터에 개봉 기록이 자동 이동하지 않는다.
- 현재 구현의 자세한 설명은 [advent_calendar.md](advent_calendar.md)를 참고한다.

### 검증과 전달 상태

- 최신 관련 테스트: `test/advent_provider_test.dart`, `test/village_scene_test.dart`, `test/widget_test.dart` **12개 모두 통과**. 잠금 경계·누적 표시·선물·저장·복원·초기화·320/600/1000px 배치를 확인했다.
- 수정 관련 5개 파일의 정적 분석은 **No issues found**였다. 전체 테스트·최종 릴리스 빌드·모바일 실기기 검증은 아직 성공을 재확인하지 않았다. 상세 파일 목록과 기존 티켓 드래그 테스트 이슈는 [WORK_HANDOFF.md](WORK_HANDOFF.md)에 기록했다.
- `flutter test test/village_scene_test.dart --dart-define=VILLAGE_PREVIEW=true`로 Windows에서 장면 미리보기를 재생성할 수 있다. `build/village_preview/closed.png`, `opened.png`, `day02_opened.png`, `day12_opened.png`를 생성·열람했다. 미리보기 옵션은 Windows 폰트를 사용하며 일반 테스트에는 필요하지 않다.

- 정리 시점 로컬 HEAD와 로컬 `origin/main`은 `62fa7ef`이며 오늘 작업은 **아직 미커밋**이다. 원격을 다시 fetch하거나 에이전트가 commit·push하지 않았다. 새 village 코드·테스트, 문서, 실행 PNG가 untracked인 상태도 포함하므로 다른 컴퓨터에서 이어가기 전 함께 커밋·push해야 한다.
- 이전 bakery 파일의 삭제는 이름 변경에 따른 것이다. 자동 복원하지 않는다. 사용자가 수정한 PPT·자료 이동·작업용 이미지도 따로 검토하고, Office의 `~$` 잠금 파일은 커밋에서 제외한다.

## 다른 컴퓨터에서 이어서 작업할 때

1. 문서와 필요한 코드·이미지가 커밋·push되어 해당 컴퓨터에 전달됐는지 확인한다. 문서 작성만으로 서버에 자동 전송되지는 않는다. 별도 로컬 변경이 있으면 덮어쓰기 전에 확인한다.
2. 최신 [WORK_HANDOFF.md](WORK_HANDOFF.md), 이 문서, [advent_calendar.md](advent_calendar.md)를 읽고 실제 코드·에셋 상태를 확인한다. 초기 빵집 1~3일 설명이 남은 다른 기록보다 최신 마을 구현을 우선한다.
3. 다음 구현 요청의 범위를 확인한 뒤 작업한다. 이 계획을 기록했다는 이유만으로 25일 전체 구현을 시작하거나 완료된 것으로 해석하지 않는다.
4. 날짜별 이미지·레이어와 터치 좌표를 확인하고, 날짜 설정 → 레이어 → 터치 영역 → `pubspec.yaml` 에셋 등록 순서로 연결한다. 2~25일 에셋이 모두 준비됐다고 가정하지 않는다.
5. 기존 개봉·재열람·저장·복원을 유지하며, 날짜별 누적 변화·야외 주민 수·트리 변화 단계를 두 표와 대조한다.

이미지 파일명은 위 표를 따른다. 1일·2일·12일의 터치 좌표와 임시 선물 제목·문구는 코드에 들어 있다. 나머지 날짜의 세부 터치 좌표·선물 제목·문구는 작업할 때 확인한다. 현재 코드는 날짜별 잠금을 판단하며 이전 날짜를 반드시 열도록 강제하지 않는다. 개봉 순서를 강제하도록 바꾸는 결정은 아직 하지 않았다.
