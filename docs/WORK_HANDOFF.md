# 작업 인수인계: 크리스마스 어드벤트 캘린더

> 작성일: 2026-11-04. 다른 컴퓨터 또는 새로운 AI 대화에서 이어갈 때 먼저 읽을 문서.
> 작성 직전 로컬 HEAD: `ef8143c` (`base changes for advent calendar. including setting, test images, etc`). 작업 트리는 깨끗했음. 원격 서버에 push됐는지는 이 문서 작성 시 확인하지 않음.

## 1. 프로젝트와 지금까지의 방향

- 저장소 폴더 이름은 `gacha_kodex`, Dart 패키지 이름은 **`gacha_codex`**이다. import 작성 시 구분한다.
- 기존 Flutter 가챠 앱에 어드벤트 모드를 추가하는 작업이다. 기존 가챠·결과·현황·설정을 유지한다.
- 처음에는 설정 스위치, 홈 문구 변경, 조건부 Calendar 탭과 24개 선물 칸을 구현했다.
- 이후 사용자가 원한 방향은 **달력에 그림을 꾸미는 화면보다, 크리스마스 장면 속 문·창문·장식에 날짜가 자연스럽게 들어가는 화면**이었다.
- 최종 목표는 **12월 1~25일**이다. 초기 대화의 24일 기준보다 이후 명시된 25일 요구사항을 우선한다.
- 그림책풍의 눈 덮인 마을이 하루씩 밝아지고, 선물을 연 흔적이 장면에 누적되는 경험을 지향한다.
- 현재 범위는 **빵집 하나와 1~3일**이다. 전체 마을이나 4~25일 콘텐츠까지 구현한 상태가 아니다.

## 2. 사용자의 작업 선호와 범위

- 설명이나 설계 제안에서 끝내지 않고 실행 가능한 프로토타입을 원한다.
- 요구사항에 문제가 있거나 중요한 모호함이 있으면 코드 수정 전에 질문한다.
- 과도한 범용 프레임워크보다 이해하고 수정하기 쉬운 구조를 선호한다.
- 기존 프로젝트 구조와 디자인 관례를 유지한다. 구현 당시 프로젝트 및 확인한 상위 경로에서 적용할 `AGENTS.md`는 발견되지 않았다. 새 환경에서는 다시 확인한다.
- 임시 에셋은 로컬에서 직접 만들며, 외부 이미지 다운로드나 사용자 이미지 제공을 전제로 하지 않는다.
- PPT 연동, 투명 여백 자동 자르기, 실제 경첩 회전, 전체 마을 제작은 이번 범위 밖이다.
- 실제 그림으로 바꾸거나 범위를 확장하는 작업은 다음 요청을 확인한 뒤 진행한다.

## 3. 현재 구현된 동작

### 앱 진입

Settings에서 **크리스마스 어드벤트 모드**를 켜면 홈 문구·색상이 바뀌고 하단에 **Calendar** 탭이 나타난다. 모드를 끄면 원래 구성으로 돌아간다. 모드 설정은 가챠 설정과 별도로 저장하므로 티켓 초기화를 유발하지 않는다.

### 빵집

| 상태 | 장면 |
|---|---|
| 초기 | 어두운 창문, 닫힌 문. 조명·빵·리스는 없음 |
| 1일 개봉 | 창문에 따뜻한 조명이 켜짐 |
| 2일 개봉 | 닫힌 문이 사라지고 열린 문·밝은 실내·빵 진열대가 나타남 |
| 3일 개봉 | 간판 옆에 리스가 추가됨 |
| 모두 개봉 | 조명·열린 문·빵·리스가 함께 유지됨 |

- 숫자를 누르면 날짜별 임시 선물 팝업을 연다.
- 이미 개봉한 날짜는 다시 눌러 선물을 볼 수 있다.
- 잠긴 날짜는 개봉 가능 날짜를 안내하며 기록을 변경하지 않는다.
- 날짜를 반드시 1→2→3 순서로 열도록 강제하지는 않는다. 각 날짜의 시각 조건을 판단한다.
- 개봉 시 변화만 애니메이션으로 표시한다. 기록 복원과 선물 재열람에서는 등장 애니메이션을 반복하지 않는다.
- 개봉 기록 저장이 성공한 뒤 화면을 갱신한다. 실패하면 기존 상태를 유지하고 안내한다.
- 눈은 현재 정적인 배경 장식이다. 지속적으로 내리는 눈 애니메이션은 구현하지 않았다.

## 4. 핵심 구조와 파일

| 파일 | 역할 |
|---|---|
| `lib/advent/bakery_config.dart` | 날짜·선물, 이미지 레이어, 터치 영역 설정과 색상 |
| `lib/providers/advent_provider.dart` | 개봉 판정, 날짜별 상태 저장·복원, 개발용 시각/옵션 |
| `lib/widgets/bakery_scene.dart` | 기준 캔버스, 이미지 전환, 별도 숫자·터치 영역 |
| `lib/pages/calendar_page.dart` | Calendar 화면, 잠금 안내, 선물 팝업 |
| `lib/widgets/advent_debug_panel.dart` | 개발용 테스트 패널 |
| `lib/providers/app_settings_provider.dart` | 어드벤트 모드 on/off 저장 |
| `lib/widgets/advent_home_intro.dart` | 어드벤트 홈 소개 |
| `lib/widgets/app_bottom_nav.dart` | Calendar 탭의 조건부 표시와 이동 |
| `lib/main.dart` | Provider와 `/calendar` 라우트 등록 |
| `tools/generate_advent_assets.ps1` | Windows에서 임시 투명 PNG 6개 생성 |
| `docs/advent_calendar.md` | 자세한 실행·이미지 교체·확장 안내 |

### 날짜 상태와 저장

- `AdventDay`: `dayId`, `unlockAt`, `gift`.
- `AdventDayState`: 날짜 설정과 `isOpened`.
- 실제 저장은 개봉한 날짜 ID 집합 하나이며, 이미지별 개봉 여부를 중복 저장하지 않는다.
- Provider와 SharedPreferences를 사용한다. 새 런타임 패키지를 추가하지 않았다.
- 모드 키: `advent_calendar`.
- 개봉 기록 키: `advent_opened_days_v1_<연도>`.
- 기본 시즌은 앱에서 Provider를 만들 때의 올해이며, 개봉 시각은 현지 시각 12월 1~3일 자정이다.
- 테스트 시각을 다른 연도로 바꿔도 시즌 연도와 저장 키를 바꾸지는 않는다.
- 서버 시간 확인이나 계정 간 동기화는 없다. **Git으로 코드를 옮겨도 SharedPreferences의 사용자 개봉 기록은 다른 컴퓨터로 옮겨지지 않는다.**

### 이미지와 터치 영역

- 기준 캔버스: **600 × 760**. 장면 전체에 같은 확대·축소 비율을 적용한다.
- 각 이미지의 `assetPath`, `bounds`, `zIndex`, 참조 `dayId`, `visibility`를 설정으로 관리한다.
- 표시 조건: 항상 / 해당 날짜 개봉 전 / 해당 날짜 개봉 후.
- 등장·퇴장 각각의 애니메이션 종류와 시간을 설정할 수 있다.
- `DayHotspot`은 날짜 ID와 별도 위치·크기를 가진다. 이미지가 교체돼도 터치 영역을 유지한다.
- 날짜 숫자는 Flutter에서 표시한다. PNG에 굽지 않는다.
- 문 두 상태는 `bakeryDoorBounds`를 공유한다. **고정 외관에는 교체할 문짝을 넣지 않는다.**

## 5. 에셋과 자료 파일

`assets/images/advent/`의 실행용 에셋은 다음 6개이며 `pubspec.yaml`에 각각 등록돼 있다.

- `exterior.png`
- `window_light.png`
- `closed_door.png`
- `open_door.png`
- `bread.png`
- `wreath.png`

모두 로컬 PowerShell/System.Drawing 스크립트로 만든 임시 이미지다. 현재 생성 PNG는 배치 크기의 2배 해상도다. 실제 그림으로 교체할 때는 설정의 경로·좌표와 에셋 등록을 수정하면 된다. 교체한 뒤 생성 스크립트를 다시 실행하면 같은 이름의 6개 PNG가 덮어써지므로 주의한다.

같은 폴더의 `Full_image.png`, `description_table.xlsx`는 현재 화면에서 사용하지 않는다. 사용자 자료로 남겨둔 파일이며 내용 분석이나 연동을 완료한 것으로 간주하지 않는다. `devtools_options.yaml`은 DevTools 설정으로 기능 실행의 핵심 파일은 아니다.

## 6. 다른 컴퓨터에서 시작하는 순서

저장소가 이미 있다면 작업하던 브랜치에서 `git pull`한다. 새 컴퓨터라면 저장소를 `git clone`한 뒤 해당 폴더와 브랜치를 연다. 개인 컴퓨터에 별도 변경이 있다면 먼저 확인하고, 강제로 덮어쓰지 않는다.

```sh
flutter --version
flutter pub get
flutter run -d chrome
```

이전 환경에서 확인한 버전은 Flutter **3.41.4**, Dart **3.11.1**이다. 새 환경에서도 SDK 버전을 확인한다.

Settings → 어드벤트 모드 켜기 → Calendar → 아래의 개발용 테스트 패널:

1. `11/30`으로 설정해서 잠긴 날짜를 눌러본다.
2. `12/1`, `12/2`, `12/3`을 선택해 각 날짜를 열어본다.
3. 같은 숫자를 다시 눌러 선물 재열람을 확인한다.
4. 앱을 다시 실행해 개봉 상태를 확인한다.
5. 터치 영역 표시와 초기화를 확인한다.

패널에는 날짜·시간 직접 선택, 실제 시각으로 복귀, 잠금 무시도 있다. 옵션 자체는 개봉 기록을 자동으로 바꾸지 않으며 세션에만 유지된다. `kDebugMode`로 보호되어 profile/release에서는 사용할 수 없다.

## 7. 검증 결과와 아직 확인할 부분

이 대화에서 **종료 결과까지 확인한 항목**:

- `test/advent_provider_test.dart`: 상태 관련 테스트 **4개 통과**.
- `test/bakery_scene_test.dart` + `test/widget_test.dart`: 위젯 테스트 **7개 통과**.
- 초기·개봉 완료 장면 PNG를 생성하는 별도 테스트 **1개 통과**.
- 검증 범위: 잠금 경계, 누적 변화, 재열람, 저장·복원·초기화, 복원 시 애니메이션 생략, 320/600/1000px에서 이미지와 터치 영역 정렬.

**완료로 단정하지 말고 확인할 항목**:

- 최종 `flutter analyze`, 전체 `flutter test`, `flutter build web --release`를 실행했지만, 대화가 다른 작업으로 전환되기 전 최종 종료 결과를 모두 확인하지 못했다.
- 웹 빌드는 Wasm dry run 성공 메시지까지 확인했다. 이것만으로 전체 릴리스 빌드 성공을 의미하지 않는다.
- 이전 검사에서는 기존 가챠의 `ticket_tear_dialog_test.dart` 중 `cancelled drag resets without consuming the ticket` 테스트가 단독 실행에서도 실패했다. 이번 빵집 기능과 직접 연결되지 않은 기존 문제이며 수정하지 않았다.
- 이전 기본 모드 작업 당시 분석에는 기존 정보성 lint 6건이 있었다. 최종 프로토타입의 분석 결과와 혼동하지 않는다.
- 실제 모바일 기기에서의 수동 실행·조작성 확인은 완료하지 않았다.
- PNG 출력물은 생성했지만 최종 두 장을 모두 시각적으로 검토 완료한 것은 아니다. 필요하면 재생성해 확인한다.

재확인 명령:

```sh
flutter test test/advent_provider_test.dart test/bakery_scene_test.dart test/widget_test.dart
flutter test
flutter analyze
flutter build web --release
```

Windows에서 미리보기 생성:

```sh
flutter test test/bakery_scene_test.dart --dart-define=BAKERY_PREVIEW=true
```

이 옵션은 Windows의 맑은 고딕 폰트를 읽는다. 다른 OS에서는 해당 옵션 없이 일반 테스트를 실행하거나 폰트 경로를 조정한다. 출력물은 `build/advent_preview/closed.png`, `opened.png`이며 `build/`는 Git에서 제외된다. 캡처 테스트에는 비동기 이미지 로딩을 기다리는 처리가 추가되어 있다.

## 9. Git과 대화 맥락

- 사용자는 혼자 개발하며 회사/개인 컴퓨터에서 이어서 작업하려 한다.
- `commit`은 현재 컴퓨터에 버전 기록을 만들고, `push`는 그 기록을 원격 저장소에 전송한다. 다른 컴퓨터에서는 `pull` 또는 최초 `clone`으로 가져온다.
- 현재처럼 한 작업을 이어갈 때는 기존 브랜치로 충분하다. 큰 실험을 기존 버전과 분리할 필요가 생기면 기능 브랜치를 사용할 수 있다.
- 사용자가 직접 커밋·푸시하려 했으며, 에이전트가 대신 push한 것은 아니다.
- ChatGPT 웹의 `pjt advent` 대화 전체가 이 개발 대화에 자동 전달된다고 가정하지 않는다. 다른 대화에서 확정한 요구사항이나 이미지는 별도로 제공받아야 한다.
- 새 AI 대화에는 다음처럼 요청하면 된다:

> `docs/WORK_HANDOFF.md`와 `docs/advent_calendar.md`, 현재 프로젝트 및 AGENTS.md를 먼저 읽어줘. 어드벤트 빵집 1~3일 프로토타입이 구현돼 있어. 기존 가챠를 보존하고, 완료된 작업을 다시 만들지 말고 현재 코드와 검증 상태를 확인한 뒤 내가 요청하는 다음 작업을 이어가줘.
